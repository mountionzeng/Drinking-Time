# 持续对话与表达探索

用户授权：2026-11-01，继承原协调会话。覆盖电脑网页、手机网页与原生小程序。

## 要达到的体验

用户带来文字、图片或录音后，可以继续聊里面的人、事、选择和感受，也可以尝试不同表达。聊天有承接，短回答不被当成结束；明确暂停时停止。每日一问从用户已愿意使用的材料中找一条尚未展开的线索，回答后仍留在同一条探索里。

保留现有「整理文字／生成图片／记忆」等明确动作，不增加一套问卷、打分或人格测评界面。艺术探索是一起试小段文字、画面或声音表达，用户可以说“不像我”。试过不等于喜欢，喜欢当前作品不等于固定身份。

## 信息边界

- 第一层：用户提供的事实与原材料，带来源；亲述与已核实事实不混同，小说角色不当作作者本人。
- 第二层：用户在具体情境中的选择和自述情绪，保留时间、对象和否定范围。
- 系统理解：只提出有依据、允许纠正的假设。不能从一次选择确定人格、诊断心理或推断隐私；情绪与美术/音乐/文学风格没有一一对应关系。
- 风格偏好：用具体表达试样和明确反馈积累，当前要求优先。用户可停用或纠正已有参考。复用现有个人记忆与文风证据机制，不另建画像数据库，不启用模型训练，不更改捕获/供应商/预算开关。
- 聊天引用不自动采用到作品，原素材、当前稿、历史版本、账务和归属校验保持有效。

## 首轮发现与改动

1. Web `writingCompanion` 每轮在最近历史之后注入开场问题，导致模型把旧问题当成最新话头；改为开场处的背景，已存在则不重复。
2. Web 帮写规则把“记不清／随便写写”与停止混在一起；改为只放下被拒绝的方向，保留用户当前愿意聊的内容。
3. 原生 `chatInterview.loadStoryContext` 将本地 blockId 当成受限来源，普通模块故事会触发错误并落入三句循环本地问题；区分编辑器 ID 与受限来源协议，继续拒绝未获授权的来源。
4. 原生只接着一段记忆聊时，旧正文常只有开场 72 字缩略；把所选记忆正文作为明确的上下文传递，保留来源范围。
5. 每日一问模型只见截断的文章开头、简单问题字符串历史，缺少“为什么问”和“问过什么线索”的承接；均衡给出已保存素材片段，带出真实原文依据和待展开线索，换题保留问题与线索历史，防止改词重问。
6. 两端沿用共同的探索原则；优先接住具体意思，必要时只问一件事，提供短小而可纠正的表达尝试，不为继续聊天制造隐私问题。

## 验收

- 同一开场连续聊三轮，开场不再次插到最后；纠正优先于旧说法。
- “记不清”“不想聊这个”“随便写写”允许换角度；“今天到这里”正常收尾。
- 普通文字模块可读取，受限来源和跨账号材料继续拒绝。
- 每日问题引用实际来源，已问过的同一线索不重复；新答案和此前已知事实进入下一次选题背景。
- 文字/画面/音乐风格试探不自动触发付费媒体生成，不擅自将候选当作认可偏好。
- 单元/集成与真实模型效果分开记录；没有云部署、真机测试时不得宣称小程序已生效。

## 后续仍要补齐

长对话的语义质量需要持续评估；先复用已有可查看/纠正/忘记的个人记忆机制。Web 后台长期提炼仍有上线门槛，不能用提示词修改宣称已经自动学会所有偏好。原生每日问题目前为设备本地缓存，不宣称跨设备题目历史同步。两端身份/记忆互通应沿已有明确账号关联范围推进，不把独立账号直接合并。
