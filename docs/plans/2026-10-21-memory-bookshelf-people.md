# 回忆：故事书架与人物关系

日期：2026-10-21。状态：用户于本轮明确回复“确定”，已批准新增表及部署执行迁移；实现、自动化及本地浏览器验证、生产迁移和 dist 发布完成，正式站双真实账号体验待用户验收。

## 用户已确认的范围

- 手机与电脑使用同一后端、同一账号数据，呈现方式适配屏幕。
- 账号「回忆」分「故事」「人」两个主界面；具体故事不恢复独立回忆页，聊天继续承载故事记事。
- 故事像书一样放在书架上，用户可以增加书架层、命名、调整层次和书的顺序。
- 打开书能阅读故事、查看参与编辑的人及编辑时间；故事更新后在回忆里有标记。
- 「人」同时呈现邀请／共创联系和用户自己标注的亲友关系，不能仅实现其中一种。
- 推送和部署已获总体授权。数据库迁移仍遵守用户要求，必须单独明确批准。

## 现有能力与证据

| 现有能力 | 权威位置 | 本次处理 |
| --- | --- | --- |
| 账号故事及封面 | `server/repositories/stories.ts` 的 `listUserStories` | 覆盖账号全部故事，不复用最近 40 篇的提醒查询 |
| 故事正文及版本 | `shared/publishingDraft.ts`、`shared/textDraftHistory.ts` | 一篇 Story 对应一本书，版本在书内展示；不复制正文到书架 |
| 共创文字与排版 | `server/repositories/sharedStoryActions.ts`、`shared/sharedLayout.ts` | 展示有记录的贡献者、提交时间和采用状态；候选不冒充已采用正文 |
| 已接受分享 | `story_context_shares`／`artwork_shares` 与 `story_context_share_imports` | 服务端关联可验证的承接关系，两类分享都覆盖 |
| 账号记忆卡 | `MemoryWarehouse.tsx`、`MobileContentLibrary.tsx` | 在账号回忆中保留「记事工具」入口，继续选卡成文、归档／恢复与来源追溯 |
| 旧分享回来提醒 | `shared/shareBackInbox.ts` | 保留原行为；新书架更新标记独立实现，不静默修改旧提醒的 40 篇／本机已读语义 |

账本：`writing-memory-warehouse`、`memory-driven-production`、`shared-story-collaboration` 为 observing；`recent-story-entry` 为 working。书架自定义排序仅作用于书架，不改变首页最近故事口径。

实际数据缺口：

- `users` 没有通用偏好或布局 JSON 字段，没有可直接复用的账号级书架／联系人存储。
- 内测邀请码和赠送卡记录有领取人，没有邀请者；不能把管理员的全站邀请码名单当成个人联系人。
- 分享回执能证明承接，不能证明链接发给了谁。旧的未接受邀请不能自动恢复，可由用户手动补录人物及「已邀请」备注。
- 分享回执没有时间列；不得把分享创建时间或副本最后修改时间冒充接受邀请时间。
- 共创记录能证明参与某篇故事，不证明两位贡献者相互邀请或现实中相识。

## 页面与操作

沿用拾光浅绿、纸感和现有字体。以书封、书脊和横向层板形成书架，不以统计卡片代替书架。

1. 回忆顶部为「故事／人」切换；次级「记事工具」保留已有能力。
2. 故事页默认「未分层」，已有全部 Story 可达；已有正文或成功候选可阅读，只有对话的条目标明「尚未成文」，不冒充成稿。支持搜索、增加／重命名层、层上移下移、书跨层移动及层内排序。移除层只把书移回未分层，不删除故事。
3. 手机以封面列阵搭配横向层板，点击书打开阅读页；整理模式用明确的「移到…／前移／后移」操作，触摸和键盘均可用。电脑增加可见书数，复用同一整理操作和数据。
4. 阅读页展示正式正文、已有版本、最近内容修改时间，以及「参与这篇故事的人」。朋友未采用版本独立标注为待确认，可进入原编辑入口采用；只打开阅读不能自动采用。
5. 人物页以列表为主，详情列出邀请／承接来源、共同参与的故事、与我及其他人物的手动关系。系统证据和「我标注的关系」区分展示；关系标签支持家人、朋友和自定义文字。
6. 无账户关联的人物可手动添加；同名不自动合并。真实账号只能依据服务端验证过的分享／贡献记录关联，前端不得填写任意用户 ID。
7. 阅读与整理之间使用轻量展开／淡入；减少动态偏好关闭非必要动画。加载、空库、错误重试、保存中和冲突状态均要明确。

## 更新标记

- 对正文／可阅读版本和共创提交计算稳定内容指纹，不单用 Story.updatedAt：聊天、书架整理等无关写入不应标记正文更新。
- 分别展示「内容有更新」与「朋友分享回来待处理」。读过候选不等于采用或忽略。
- 成功展示故事详情后，记录该次实际展示的内容指纹；后台出现新版本时不能被旧读回执清掉。
- 首次建立书架以现有内容为阅读基线，已有待处理共创仍显示。后续新故事显示「新故事」。
- 新书架已读标记保存在账号后端，手机和电脑重读后同步；旧菜单提醒本机已读保持既有语义。

## 已批准的数据增量

建议只新增 `account_memory_spaces` 一张账号级表，不修改故事、版本、分享、账号等现有表。不借用故事正文、长期记忆理解或服务器文件存书架数据。

以下为原审阅 SQL 草案。已生成等价的 `0033_account_memory_spaces` 迁移；实际外键名遵循 Drizzle 生成命名。正式库执行时间以 QA 发布记录为准。

```sql
CREATE TABLE `account_memory_spaces` (
  `userId` int NOT NULL,
  `revision` int unsigned NOT NULL DEFAULT 0,
  `state` json NOT NULL,
  `createdAt` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updatedAt` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP
    ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`userId`),
  CONSTRAINT `account_memory_spaces_owner_fk`
    FOREIGN KEY (`userId`) REFERENCES `users` (`id`) ON DELETE CASCADE
);
```

`state` 为带 schemaVersion 的专用结构：

| 字段 | 内容与约束 |
| --- | --- |
| shelves | 随机层 ID、名称和有序 Story ID；每本书至多属于一层，层顺序即数组顺序 |
| seenStories | Story ID、已读内容指纹；只记录当前账号可访问的故事 |
| people | 随机联系人 ID、自填称呼、备注、服务端确认的账号关联（仅服务端使用） |
| relationships | 两端联系人 ID 或「我」、用户填写的关系名称；明确方向，支持修改和删除 |
| initializedAt | 首次建立阅读基线时间，避免把全库历史都误标成新更新 |

邀请／共同编辑边从现有权威数据查询得到，不存为用户可伪造的系统事实。手动「已邀请」备注只代表用户记录。手动关系只对当前账号可见，不通知对方、不改变对方联系人或权限。

服务端约束：

- 所有操作从登录上下文获取 owner。只接受具体操作，不接受前端整包覆盖 state；故事和关系端点重新校验归属。
- 修改使用 revision 条件写入；冲突保留用户输入并重新加载，不能后写覆盖先写。读回执由服务端合并，并验证展示版本，避免覆盖并发整理。
- 联系人使用随机公开 ID；返回显式 DTO 白名单，不返回贡献者 userId、分享 token/tokenHash、requestHash、邮箱或手机号，不直接序列化内部 state。
- 同一作者故事里的两位贡献者可显示「共同参与这篇故事」；不读取他人的私人故事、聊天、记忆或私有社交关系。
- 删除故事后，失效书架引用不可再读取正文；不得因书架排序／读回执生成新的故事修改时间。删除账号级书架设置不能删除故事。
- 本地模式接入既有 runtime 持久化和锁，不新建独立业务文件；隔离测试不写真实 `.webdev`。
- JSON 使用大小与条目上限校验，超限明确报错，不能静默截断；对全库读取分页处理，列表不携带全文。
