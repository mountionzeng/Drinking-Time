## 已确认规则

邮箱和微信均可独立注册、登录及使用产品。任何一侧不得强制绑定另一侧。绑定是登录后的可选操作：邮箱账号可绑定微信，微信账号可绑定邮箱。绑定完成后，两种身份指向同一 userId，共用故事、对话、正文与账本。

邮箱继续支持现有验证码和密码。邀请邮件的一次性登录链接是新增登录方式，不能把现有设备配对码当作邮件登录令牌。微信网页登录与小游戏微信登录需要分别接入适用的官方授权流程；不同 AppID 的 openid 不能直接相等比较，UnionID 缺失不自动创建关联。

## 绑定流程

1. 已登录用户发起绑定挑战，服务端从当前会话确定账号，绑定目的与普通登录分开。
2. 验证目标身份：邮箱验证码或微信服务端 code 交换。客户端不得自行声明验证成功。
3. 目标身份未被占用时，经过明确确认，在事务中添加身份，保留当前 userId 和已有数据。
4. 已绑定同一 userId 时幂等成功。
5. 已绑定其他 userId 时，返回需要账号合并的状态；不得自动重绑、搬数据或相加余额。验证双方身份并确认合并方案后，才允许独立合并流程。
6. 一次性链接码必须绑定发起账号、用途、过期时间与接收身份，限制尝试并原子消费；输入码不等于静默获准登录或转移所有权。
7. 解绑前检查仍有可用登录方式，并要求近期身份验证。

## 数据保护

邮件链接令牌只存摘要，短时有效且一次性消费。邮件扫描器 GET 访问不得直接消费令牌或执行绑定。绑定前后的会话与草稿作用域要明确，不能把上一身份的草稿写入下一身份。不得绕过 Web Origin/CSRF 策略来兼容小游戏；小游戏使用独立可撤销服务端会话。AppSecret 仅在服务器配置，不放入包或聊天。

已有两账号的合并需覆盖故事所有权、聊天、正文版本、个人记忆、邀请赠送与消费账本，并处理进行中的付费任务。没有完成这些迁移与回滚验证之前，冲突应提供解释与后续处理入口，不声称已合并。
