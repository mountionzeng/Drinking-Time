# 桌面对话可操作能力

权威契约：`shared/studioAssistant.ts` 的 `STUDIO_CAPABILITIES`。入口为 `/editing` 原聊天，作用域始终来自当前登录账号和当前故事。模型只选择经校验的工具，执行回执决定回复；没有工具成功回执不得宣称已经完成。

| 用户界面动作 | 对话工具 | 实现与行为 |
| --- | --- | --- |
| 了解当前页、故事、选区及保存状态 | `inspect_workspace` | 每轮固定 UI 快照，标题由服务端验证归属后读取；不是截图，不据此猜画面 |
| 打开书、视频、分镜、仓库 | `open_workspace` | 现有工作区切换与仓库抽屉；迟到结果不切换新页面 |
| 浏览与打开自己的故事 | `list_stories` / `open_story` | 自己的故事列表；按确切标题或编号定位，沿用现有离开草稿保护 |
| 查看故事联系人、打开邮箱/联系人 | `list_contacts` / `open_mailbox` | 已建立的故事分享关系；同名可按列表编号继续对话 |
| 查看朋友保存了什么变化 | `read_correspondence` | 复用邮箱刷新与作者署名记录，最近30条；停止联系后只读旧记录 |
| 列出可分享部分 | `list_story_parts` | 已保存段落、图片、视频、声音及成片；使用服务端返回身份，不能猜编号 |
| 向朋友发送整篇或所选部分 | `send_story` | 明确选择或复用邮箱当前勾选；先预览目标与固定范围，回复“确认发送”执行 |
| 私密接收到本人小程序 | `send_to_wechat` | 聊天确认后准备接收二维码；本人手机确认后入私密来稿，用户再选择微信好友 |
| 独立接收一份来稿或最新稿 | `receive_version` | 回复“确认接收”，通过现有幂等接收服务；保留原稿，打开新副本 |
| 停止后续共享 | `remove_contact` | 回复“确认停止联系”；双方停止共享，旧作品与往来保留 |
| 取消尚未确认的操作 | 本地确认会话 | “取消操作”；换账号、故事、页面、联系人或邮箱选区/目的地亦失效 |
| 已有文字选区、书稿/排版讨论 | 原 writing companion / selection 编辑 | 保留每轮快照与明确采用规则，普通聊天也带当前 UI 状态 |
| 已有剪辑、声音、美术/候选操作 | 原 editingCommandRunner 与专项聊天处理器 | 按原功能卡范围工作，本次不扩充付费权限，不绕过报价或采用 |

新工具通过 `studioAssistant.chat` / `studioAssistant.confirm` 两个鉴权入口执行；邮箱变更复用页面相同的仓库函数。签名确认绑定账号、发起故事、具体目标、快照指纹及10分钟期限；发送重试复用请求ID，接收复用来稿ID。确认令牌不进入故事、聊天记录或模型上下文。

正文、标题、联系人称呼、来稿附言均为数据，不是执行指令。普通写作不因此被强制转换为页面操作。仅页面操作的对话不能自动变成一个空故事。

未覆盖全部界面按钮：创建/搜索陌生联系人、批量连续执行、旧来往翻页、账号设置、全部排版控件和原生小程序全部操作目前没有统一工具；不宣称全站动作已全部打通。模型理解任意口语的效果、真实浏览器并排邮箱与聊天的交互仍需实际验收。法语支持部分工具文案，其他回复回退英文。
