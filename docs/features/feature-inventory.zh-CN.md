## 仍在观察或尚不能运行完整的功能

### 0. 单一开发环境：当前损坏

`pnpm env:status` 已确认同时存在两个服务：主仓库端口 3000（PID 71871）和 `login-copy-refer` worktree 端口 3050（PID 46287）。后者拥有自己的 `.webdev/local-persist.json`，因此已经形成真实的数据分裂风险。当前共有 5 个 worktree 带本地数据文件。按本轮约束没有停止任何服务，也没有删除任何数据；需要由拥有该服务的任务先安全收尾。

### 1. 私人美术策展库：观察中

去重导入、目录、清洗后美术 DNA 的读取边界和付费确认闸门已有实现与测试，但 99 张参考图仍处于 `pending-analysis`；实现尚未提交，也没有迁移到私有对象存储。现在可以管理“待分析清单”，不能把它描述为已经完成的线上美术学习系统。

### 2. 提示词评测与重复修改反馈闭环：观察中

本地 `main` 上的 11 个评测文件、94 项测试已经通过；68 个冻结镜头、204 个样本没有指标回归，TF-IDF 差异率为 2.10%，且只影响旧版消息。但当前评测评分的是 `compilePromptTargets().finalText`，静态图片供应商实际接收的是 `engineerImagePrompt()` / `renderViaGate()` 输出。因此它还没有闭合“评测对象就是供应商最终收到内容”这个承诺。

合并前需要明确选择一种语义：

1. 保留两级编译，并分别评测谱系输出与 Render Gate 最终输出；优点是职责清楚，代价是维护两套指标。
2. 让谱系 `finalText` 直接成为 Render Gate 输入；优点是评测对象统一，代价是会改变当前提示词编译语义和调用边界。

在用户明确选择前，不应自行合并或改写这条链路。

### 3. 实时社交媒体语境适配：仅计划

当前可运行的是“用途与受众识别”，不是实时趋势理解。尚未确定外部数据源、刷新策略、成本和生成入口，不能把两者混为一个功能。

## 优化优先级

### P0：先消除分支与提示词语义分叉

当前最新静态图、质检、私人策展实现仍在未提交工作区，而提示词评测在本地 `main`。继续叠加功能会增加丢失和冲突概率。应先由用户决定上述两级编译语义，再做分支收敛、完整复测和提交。

### P1：拆分发布工作台

`PublishingDraftWorkspace.tsx` 已约 2362 行，承担版本、平台稿、封面、意图、视频交接和多种异步状态。建议按“版本与意图”“平台稿”“封面生成与恢复”“视频交接”拆为边界清晰的组件/状态模块，同时保留一个跨层集成测试验证真实用户链路。

### P1：把功能账本校验接入持续检查

目前 `pnpm feature:validate` 可以人工执行，但 CI 尚未强制。接入持续检查后，缺失代码归属、无测试却标记 `working`、未知依赖和替代关系循环会在合并前失败，进一步降低“功能写完后被忘记”的概率。

### P2：降低测试日志噪音

部分故障注入测试会打印预期错误。可以为这些用例局部捕获并断言日志，保留失败证据同时让真实错误更醒目。

### P2：清理历史环境副本

当前 5 个 worktree 含本地数据文件，其中 `login-copy-refer` 的副本正在被端口 3050 使用。先让拥有该任务的会话安全停止并确认未产生需要合并的数据，再核对备份和主数据，最后才做受控清理；在确认前不应直接删除。

## 以后 Agent 应怎样避免浪费算力

1. 开工前读取 `docs/features/feature-ledger.json`，先告诉用户相关旧功能和不可破坏约束。
2. 可能覆盖旧功能时硬暂停，明确说明替代关系和取舍，等待批准。
3. 新增持久能力建功能卡；普通修复和重构写进所属卡历史，避免账本本身膨胀。
4. 完工必须留下真实入口、权威代码、可执行测试和已知缺口；只有计划或页面存在不能标记为可工作。
5. 运行 `pnpm feature:validate`，再用代码健康快照观察规模、风险函数、可能无用函数、重复概念、环境分裂和监听器/数据文件增长。
