# 手机“基于当前内容生成”入口修复

原因：此前手机同名入口调用 textDrafts.generate，且 source 缺失时被禁用。
网页端实际为 StudioCreateMenu 的图片、视频、音乐、图文排版菜单。

修复后两端共用 StudioCreateMenu；菜单始终可展开，具体动作沿用故事、
聊天忙碌、音乐需镜头等前置检查。生成新版本仍使用原有候选预览及保存流程。
手机图片和图文排版打开 MobileImageStudio，并把选择和输入要求传给
PublishingImagePack。视频、音乐在新标签页打开已有制作工作区；手机聊天保留。
不自动付费、采用正文或覆盖旧稿。

跨页请求存 sessionStorage，URL 只含请求 ID 与故事 ID；接收校验账号、
故事编号、动作及十分钟有效期。复用 StoryAgentProvider 的 storyId 冷启动，
避免账户尚未恢复时提前 loadStory 无效而打开最近的其他故事。

手机聊天层为 z55，Radix 的默认弹窗/菜单为 z50；增加仅在手机聊天打开时
生效的浮层规则，保证菜单、图片确认弹窗和排版工具在聊天之上可点击。

本地验证：
- 390×844 实点手机故事 → 聊天 → 菜单，显示四项，与网页端一致。
- 图片打开要求输入及“确认生成4张”报价窗口；未点击付费确认。
- 排版直接打开模块编辑、页面与预览导出工具。
- 无镜头时音乐禁用并解释原因；切换到测试故事1202后可点音乐，
  新窗口正确打开该故事的“为整个故事生成音乐”窗口。
- 视频打开制作视频与时长选择窗口。未点击生成故事版、未调用付费模型。
- 相关六个测试文件共27项通过；pnpm check 通过。

本次未部署。视频/音乐复用现有网页制作工作区，并非新做的手机原生编辑页；
真机浏览器的新标签页行为及付费生成未验收。
