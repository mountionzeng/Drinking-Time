## 可重复的验收入口

在已保存的故事的 `StoryAgentChat` 中，可分别提出：

- “把雨夜和外婆的记忆组合成文章，设为当前来源，再生成分镜候选。”系统先解析真实卡片；重名或指代不清时澄清，不猜选。
- “查看影响。”显示使用当前文字、旧文字及来源未知的独立下游对象。
- “采用候选 <完整编号>。”先返回采用摘要；回复“确认采用”才写入正式作品。会话、提案、期限或正式内容变化会阻止旧确认。
- “查看候选 <完整编号>”“放弃候选 <完整编号>”“恢复候选 <完整编号> 的旧稿”。恢复产生新的待采用候选；保留后来新增的分镜，避免时间线素材引用失效。
- “回到记忆仓库”“回到刚才的位置”。未保存内容通过对话选择保存、放弃或取消。

上述为可重复步骤；本轮实际执行的子集与结果列在下方。第一版只接 `StoryAgentChat`；其他聊天入口、跨媒体素材最新版解析留在后续范围。

在同一内置浏览器打开新的 `http://localhost:3000/editing` 标签页后，页面可正常操作；前次连接错误不再是当前阻塞。使用既有的两张虚构雨天修伞铺记忆，在独立验收故事 1203 中操作，没有改动原故事的文章或素材。

交互计时包含电脑操作工具与页面等待开销，是单次验收样本，不是 P95。生成时间取服务端保存的创建/完成时间，不包含人工检查间隔。39 秒短文生成仍是模型等待，未声称已加速文学生成或秒回。分镜真实生成成功为 5 镜头，但未取得可比较的精确生成耗时。

实测发现并修复：

1. **新故事保存失败**：只有标题的新故事被自动保存的空内容保护挡住。显式创建允许保存空故事，自动空工作区仍不保存；失败时保留选卡。修复后该未持久化新故事成功保存并生成文章。
2. **简单指令也等待模型**：明确编号的来源切换、明确的当前文字/编号文字候选请求直接解析；查看影响、候选等操作不读取整份 500 卡目录。复杂/否定/复合表达继续走意图验证，服务端归属、歧义、CAS 与确认规则保持。
3. **采用后确认对话消失**：指令完成回执与本轮用户/助手消息一起写入 Story；已有规范对话不反复从旧 body 迁移，结构刷新后重新合并规范对话。连续执行下一条指令及整页刷新均保留最后两轮采用记录。
4. **刷新误判候选失效**：指纹按实际 JSON 保存内容计算，排除按顺序自动生成的 SH 编号差异。实际文字、镜头内容、自定义编号、顺序、素材和版本变化仍拒绝旧确认。已复测“生成 → 刷新 → 采用”。
5. **候选详情不易读**：时间线列表改用镜头名称和时长，避免展示内部镜头 UUID。

实测先确认采用分镜，再生成并采用时间线；恢复空的旧时间线为独立候选并确认采用，再从其旧稿快照恢复到 5 镜头版本。恢复过程没有重新调用模型。最终保留 Story 1203、文字 1 当前来源、5 个分镜和 5 条时间线项；发布稿仍为空，未因选择来源而自动采用。

## 顺序代码审查

按项目要求由主线程顺序审查，不作为独立多 Agent 审查。范围含本次新增文件及对既有权威写入器、仓库、文字历史和聊天入口的改动；未将同工作区移动端、个人记忆等其他会话改动纳入本次交付。

已修复：旧发布版本归一化不应凭空增加字段；候选请求 token 必须绑定原始载荷；恢复旧分镜保留新增镜头；内存持久化失败回滚候选声明；候选采用回执与正式内容原子写入；迟到对话响应按故事/版本/会话隔离；接收指令时同步清空原输入框，避免迟到响应清掉其他故事的新输入；导航中的保存失败不跨上下文提示；选卡名称不依赖仓库首页；采用结果使用结构字段通知刷新；“查看当前来源”不能授权切换来源。补齐 SSR 查询 mock 与本地集合兼容断言。

全量回归另发现已有手机号登录改动直接引用 runtime，做了等价仓储封装：`phoneLoginStorageReady()`。生产环境必须有真实数据库、短信证明、限流和身份规则保持不变，相关测试通过。

## 故障恢复

遇到结果待确认时先“查看候选”，由正式作品中的采用回执对账。重复操作不会重新调用模型。正式内容或文字来源变化后保留旧候选，重新比较并显式请求新候选；不自动覆盖人工修改。旧稿恢复仍需明确采用。只有主仓库运行 3000 服务，其他 worktree 不启动服务或写业务数据。
