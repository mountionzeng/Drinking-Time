# 文章与配图生成等待优化

## 证据与判断

- 环境：主仓唯一 3000 服务；本轮没有启动其他开发服务或修改业务数据文件。
- 既有插图任务的阶段记录见 `2026-10-02-publishing-image-pack.md`：领取至完成 155.9 秒，绘图 76.8 秒，四图保存至候选完成 18.5 秒。领取前准备未计入，不能把此数据当作完整点击耗时。
- 原 `generateCover` 在图片已下载后仍等待整批视觉质检，再登记候选和返回。质检允许 60 秒超时；业务规则实际只要求标注风险，所有已付费图片均可选。
- 独立文字版本在生成前串行读取最多 100 个故事以检索文风证据。现有本地仓库是内存读取；这项优化主要减少数据库模式的串行 I/O，不声称它解释了本机全部文章延迟。
- `invokeAgent` 已支持 JSON 协议，但 `runJsonAgent` 没有传递入口，文章生成只靠提示词约定 JSON。格式错误可能进入第二次完整修复调用；没有线上格式错误频率，不能量化本项收益。
- 当前周报主要是静态 AST 指标，runtime coverage 为 0。1223 个“高风险函数”是筛查结果，不是 1223 个已证实的故障。最大的故事板组件约 5609 行，发布工作区约 2842 行，适合按责任逐步拆分。

## 本次实现

1. 所有图片先持久化为可用候选，显示「质检中」，然后后台完成原有质检。只在有待检查候选时以 1.5 秒间隔读取状态，完成后停止。
2. 质检写入通过已有 Story CAS，只更新原 versionId/roundId/assetIds 的风险字段；保留当前文章、封面选择、其他轮次和全部付费图片。
3. 检查异常标为未完成。待检查标记 90 秒后过期为「质检未完成」，服务重启后不会永久显示正在检查，也不会自动再次付费检查。晚到的正常结果仍可回写原轮次。
4. 文字证据每批最多并发读取 4 个故事，按原近期顺序处理；用户/平台隔离、样本上限、去重和可停用学习保持。
5. 独立文字版本及旧发布稿生成/转换/改写显式请求 JSON object；保留原有解析、内容约束和错误恢复。其他 Agent 调用方式不变。

## 验证

- 先复现 JSON 参数未传递、文风读取并发为 1 的失败测试，再完成修复。
- 7 个相关文件 196 项通过；随后新增的页面质检状态用例通过，页面文件共 16 项。涵盖延迟质检尚未返回时四图已可读、失败标记、风险图片保留、重载可读、跨版本回写、归属拒绝、候选 ID 不匹配拒绝、超时降级以及文风证据读取上限。
- `pnpm check`、`pnpm build`、`git diff --check` 通过。
- 全量测试：沙箱内 4807 项通过，8 个文件因 `listen EPERM` 无法创建测试端口。使用所需权限仅复验这 8 个文件，87 项全部通过。条件性集成测试仍按既有配置跳过。
- 浏览器点击复验被 macOS 锁屏阻断；未声称真实付费出图或完整点击耗时已验收。未购买新图、未切换模型或降低图片尺寸。

## 每周回顾建议

保持现有唯一的「每周回顾」，旧独立架构报告已暂停，无需新增定时任务。每周最多推动 1–2 个有证据的问题闭环：

1. 先看真实入口：生成文章、选图、恢复已受理任务、改字后的导出、刷新后的保存。记录最近失败及可复现条件，避免只有静态页面测试。
2. 为真实生成补充分段耗时和样本数：上下文准备、模型生成、供应商绘图、下载、候选首次可见、后台质检。分别统计成功率、中位数和 P95；没有样本写“缺失”。这是后续观测工作，本轮未建立运行时统计系统。
3. 检查等待是否必要：权限、费用确认、任务回执、完整正文、CAS 必须在关键路径；提示性评估可在后台。新增检查需要说明它阻止哪种真实故障。
4. 一次只拆一个责任：优先从 `PublishingDraftWorkspace` 和 `StoryboardReviewBoard` 中抽离任务状态与恢复逻辑，保留单一数据写入入口，不按文件行数机械拆组件。
5. 周报同时记录问题负责人、修复证据、未完成项。测试环境失败与产品失败分开，静态“可能未使用”须查真实入口后再删。
