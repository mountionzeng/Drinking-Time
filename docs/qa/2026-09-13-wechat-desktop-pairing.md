# 微信故事连接电脑版测试站发布

2026-09-13，用户要求先试用微信与电脑之间的短码连接，让微信账号已有故事进入电脑网页继续生成视频。本轮选择“微信端生成码，电脑端输入”的方向，复用已有一次性设备配对能力。

## 最终行为

- 微信小游戏登录后，在“我”页点击“生成电脑登录码”；再次确认后，服务端只按当前 Bearer 会话中的 userId 签发六位短码，客户端提交的 userId 不参与授权。
- 短码五分钟有效，只能兑换一次；同一账号重新签发会作废旧的未兑换码，签发和兑换分别限流。
- 电脑登录页的“微信登录”标签显示短码输入框。兑换成功后建立该 userId 的网页会话并进入 `/editing`，用户从既有云端故事库选择故事。故事、正文、聊天、镜头、素材和余额继续使用原 storyId 与服务器归属校验，不复制或合并数据。
- 未登录微信、未明确确认、过期、重复使用、畸形码和爆破尝试均不能建立电脑会话。

## 测试站发布

后端只同步 `server/_core/minigameRouter.ts` 与 `server/_core/minigameRoutes.ts`，备份位于 `/root/dk-wechat-desktop-pair-20260913-193023`；构建后重启 `drinking-time-mobile-staging`。网页只同步 `AuthEntryPanel.tsx` 与 `LoginPage.tsx`，备份位于 `/root/dk-wechat-pair-login-20260913-193553`。两次发布都使用 staging 独占锁、完整 dist 备份和失败自动回滚，正式站未改。

发布后公网 `/healthz` 返回 `ok`，`/readyz` 返回 MySQL ready、authentication required；匿名调用 `/api/minigame/pair/issue` 返回 `401 session_expired`。网页生产包包含新的“打开微信里的故事”入口，桌面 1280×900 无登录截图验证布局正常。

专项验证：小游戏认证与视图 77 项通过；网页登录、小游戏路由及配对服务定向 29 项通过；根 TypeScript、小游戏 TypeScript 和微信联调版构建通过。自动化覆盖当前微信 userId 签发、客户端 userId 注入无效、明确确认、Bearer 传递、客户端状态清理、一次兑换、过期和限流。
