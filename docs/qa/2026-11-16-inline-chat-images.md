# 视频聊天：框内图片引用与输入可读性

本轮仅主仓 localhost:3000/editing / launch video（1217）；补丁已逐文件哈希核对后同步用于本地验收，未 commit/push/部署。两份原11月16日交接保留，继续按 Launch 第5节 → 第6节导出分享 → 协作版本隔离的顺序；本轮没有推进协作、钱包或小程序账户。

## 已交付的用户行为

- 在输入框文字间放置光标，再点仓库图片，真实缩略标签插在该位置。支持最多4张不同图片；重复提及仍保留文字位置，送模型时只附一份实际图片。删除标签移除对应引用，原生撤销可恢复。
- 仓库保持打开，最新 #2116 / V47 仍在最左。悬停框内或已发送的图片标签，显示原地址高清预览；不抢走输入焦点。
- 多行输入自然增高，超过最大高度可滚动。原四行要求不再被固定一行高度裁切；头像按钮及SVG均28px，空白和重复上下文压缩。
- 引用顺序和文字位置进入原有草稿/消息存档。改图走已有报价确认链路；看图比较走已有多模态聊天，由服务端校验所属账号/故事后读取图片，不使用最后点选图替代框内所有图片。看图请求不触发改图或自动采用。
- 报价的确认/取消按钮就在对应最新消息内部；刷新不恢复费用授权，可从该消息“重填要求，重新核对报价”。已有草稿时禁用重填，避免覆盖正在写的文字。

## 原页面操作与实际结果

1. 刷新原页面，恢复的完整原话仍在；编辑器112px高，scrollHeight同为112px，文字全部可见。空输入在上一阶段由283px压至178px，聊天可见区域由256px增加至361px；本轮多行内容按实际文字增高，不把这些空输入指标冒充多行指标。
2. 在“你需要调一下，”后插入#2110，在“云的部分再多一点。”后插入#2116。DOM顺序为文字→2110→文字→2116→文字，仓库仍开；编辑器140px与scrollHeight相同，无裁切。
3. 悬停2110：实际原图960×960，焦点仍在输入框；刷新后两张图片与相邻文字位置保留。删2116标签后只剩2110，撤销后两张都恢复。
4. 移除临时第二张引用，恢复原话，只引用原来选择的2110。发送得到本地待确认报价2.86算力，聊天出现真实缩略图和完整原话。第一次发现报价按钮在消息外而未跟随滚动，已修为消息内。再次核对时按钮位于571–597px，聊天底部618px，实际可见。
5. 第二次报价是验证按钮位置的本地报价，没有调用模型。已点击取消，聊天明确记录未生成、未扣费。将原话与2110重填回输入框后刷新，草稿及已发送缩略图均保留，确认生成按钮数量为0。最终原话保留，仓库打开，头像/按钮28px，输入138px且scrollHeight同为138px。
6. 点“回到最新对话”可定位最新取消回执。刷新后的初始滚动可能落在消息后的素材历史区，本轮未宣称修复这一独立定位问题；已将最终原页面定位回最新回执。

## 检查、失败与边界

- 最终专项覆盖 inlineChatImages、inlineChatDraft、模型消息内容/归属校验、原聊天路由、选图报价、暂停帧和仓库；对应日志 inline-chat-tests.log / inline-chat-route-tests.log。原图预览先前3项及前一阶段61/15项记录保留。
- 类型检查和标准build通过，build包含77项草稿安全门禁。scope使用原暂缓清单，未放宽；feature账本验证记录单独保存。
- 类型检查的两次失败均属本轮新增代码：漏导入useMemo/条件分支收窄，以及测试mock调用参数类型。均已修正，未算作旧问题。
- 原页还发现头像内部64px导致缩小容器后被裁掉，已同时缩小按钮/SVG到28px；报价按钮离开最新消息的滚动问题也在实际页面发现并修复。
- 真实模型/付费生成质量未验收；测试模拟模型调用并断言实际图片内容及文字交错顺序，不能据此宣称已经完成付费改图。手机物理中文输入法未实测，组合输入与原生undo保护保留。
- 多图生成结果卡仍沿用现有控制器；付费结果的刷新恢复和后续采用不在本轮真实验收内，功能保持partial。当前整片导出分享、森林配色认可及协作仍未完成。
