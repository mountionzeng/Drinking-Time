# 故事上下文分享：首版本地验收

日期：2026-10-02。分支：`codex/story-context-sharing`。状态：实现完成，本地入口已验证；尚未部署或宣称公网可用。

## 用户操作

1. 在发布文案区点击「邀请他改写」，预览当前标题、正文和故事背景。
2. 聊天文字默认不分享；需要时勾选「同时分享本故事的聊天文字」，确认预览后创建、复制链接。
3. 持有链接的人可以阅读。登录后点击「以此开始我的故事」，建立归自己所有的新故事并进入已有编辑器。
4. 正文是可编辑起点，来源背景可展开查看；聊天和生成文稿都会读取这份有来源标识的参考资料。
5. 作者可停止该故事的全部分享链接。此前收件人已经创建的故事仍保留，双方之后独立修改。

首版交付链接，不含二维码、共享编辑或媒体复制。没有增加依赖，没有调用付费模型。分享固定在创建时，原作者后续改稿不更新旧链接；首版无自动过期。

## 内容与归属

- 分享当前编辑器可见的标题、正文、标签，无需额外应用修改或运行文风评估；背景、人物、素材卡读取已保存故事。服务端重算预览指纹，内容变化需重新确认。
- 采用文字字段白名单，不克隆完整 Story.body，不携带媒体 ID、任务、计费状态、账号记忆或登录凭据。序列化快照上限 100,000 字符，超限明确报错，不静默截断。
- 新故事使用新 ID、revision 1、收件人 userId，projectId 为空。来源聊天、素材卡和意图放在独立参考字段，收件人的聊天和素材卡为空。
- 后续普通保存保留服务端来源字段。聊天按 storyId 校验归属后读取来源；文字生成把来源独立放入提示，不加入个人记忆样本或伪造的收件人发言。
- 32 字节随机 token 仅在创建响应中返回；持久化只存 SHA-256 校验值。公开接口只返回经过筛选的快照，不能读取原 Story。
- 同一分享、同一收件人并发点击只建一个副本。创建故事与回执在本地同一持久化操作/SQL事务完成，失败回滚。
- 链接页及带返回路径的登录页设置 no-store、no-referrer 和禁止索引。Google/Supabase 授权地址不携带分享 token，返回路径由 HttpOnly 短期 Cookie 保留，且仅允许 `/m` 或合法 `/s/<token>`。

## 浏览器实测

主仓 `localhost:3000`，Chrome，使用虚构故事「分享功能验收（虚构测试）」进行测试。

- 发布文案区分享按钮可见；预览显示当前完整正文和背景，聊天复选框默认未选。
- 创建链接后可复制，并明确提示 localhost 链接只能本机打开。
- 接收页显示同一正文，展开背景能看到约定和人物资料；不会自动创建故事或生成图片。
- 点击开始进入登录页，保留同一分享路径。
- 撤销后重新打开链接显示不可用。
- 编辑器初始化后可正确打开显式指定的 storyId；在故事列表载入期间的手动切换优先于自动进入。
- 验收结束已撤销测试链接、通过主仓 API 删除仅本次生成的 Story 1201，并恢复原 Story 1199；没有修改或分享真实文章，也没有新增付费调用。

本机启用固定开发游客账号，即使切换浏览器也不是两个正式账号。浏览器验证截至登录页；正式账号承接、独立修改、权限隔离由自动化接口测试覆盖，不能等同于双账号公网浏览器验收。
