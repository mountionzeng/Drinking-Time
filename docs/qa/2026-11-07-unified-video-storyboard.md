# 同一视频双视图与自动剪辑修订

2026-11-07，本地 main，未提交、推送或部署。

## 已完成

1. 「视频 → 分镜稿」默认读取已经采用的正式镜头。与「剪辑与预览」共用 CreationEditor / StoryboardReviewBoard 控制器，切换保留选中镜头、播放位置及原生成状态。
2. 逐镜表和横向表共用 matrixShotEntries 时间轴投影，编号复用 displayShotCode，行使用稳定身份。剪辑栏移镜时，图文随其身份与时间顺序移动；未放入时间轴的镜头保留末尾。
3. 分镜稿上方复用原剪辑行（含字幕、音轨），两视图不会同时挂载两套剪辑行键盘监听。选择逐镜表镜头时定位到对应播放时间；原剪辑预览布局与默认简化行为保留。
4. 每镜一个「生成」菜单：图片、视频、声音。前两者进入原渲染检查、参数和费用确认；声音预览台词与预计算力后使用原配音服务。文字未保存或生成中不可提交；错误原位显示，已有音频保留并标明文字过期。
5. 原聊天的「查看并确认分镜」继续打开候选方案，明确显示「待核对方案」及尚未采用状态。打开、切换不采用方案；已确认方案仍是只读历史。点击顶部「分镜稿」可返回当前正式视频。
6. 正式视觉剪辑与旧时间轴保存启用自动剪辑修订，同一 CAS / 事务提交前后快照；保存失败、冲突、相同内容不新增。首次记录旧基线，最多30个状态，快照不递归携带历史。结构编辑同时留存镜头正文，字幕/音轨切片和素材引用保留。原历史入口展示当前修订号及镜头文字。

## 验证

- 19个针对性测试文件，共258项：新逐镜表、两视图、候选编辑、时间轴排序、剪辑行/预览、结构编辑/撤销、CAS及持久失败、快照保留、旧成品版本。
- `pnpm check`、`pnpm feature:validate`（86卡）与差异空白检查通过；结束时 `pnpm env:status` 确认仅主仓3000在运行。
- 主仓3000真实界面：launch video第03镜选中后切到剪辑预览，Preview显示03、播放位置00:16，2003/2004/2005三张参考图仍在。菜单显示图片/视频/声音三项，未执行生成。
- 原候选7镜方案仍显示「待确认 · 尚未采用到视频」，显式确认按钮保留。返回正式表后原选择保留。
- 修复验证过程中发现的旧镜头缺失 videoTakes 列表，以及隐藏候选工作区返回后文本框高度归零问题；最终往返视图时文字框可完整显示（例：clientHeight=scrollHeight=100）。
- 没有修改真实故事正文、镜头时间轴或候选方案，没有付费生成。剪辑移动/拆分/撤销的写入测试均使用 Vitest 隔离临时库，不写真实 `.webdev`。

## 边界

- 自动剪辑修订独立于成品 Vn，不自动完成或替换成品组合；快照记录素材引用，不复制媒体文件。
- 本次历史界面可查看镜头文字，尚未提供整条时间轴恢复；最多保留最近30个状态。
- 单元格正文编辑仍使用原字段版本；独立音频/字幕与旧兼容素材采用不统一自动建剪辑快照，下次正式剪辑会记录其当前基线。
- 生产MySQL并发、真实付费生成及导出成片未在本轮执行。书中最新候选需用户明确采用后才进入两个正式视图。
