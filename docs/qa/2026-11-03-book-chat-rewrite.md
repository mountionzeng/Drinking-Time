# 2026-11-03 聊天改写直接替换

用户要求：保持现有聊天和书稿状态，只在改写内容后加一个小按钮，点击直接替换对应内容。

## 实现与约束

- 桌面书稿选中单块、多块或跨块文字后，在发送聊天时固定模块ID、来源及字符范围。聊天队列保留这份快照，不跟随稍后的选区变化。
- 原伴写请求在同一次模型调用中区分简短说明与完整改写正文；界面显示完整正文，只有明确的改写结果才提供“替换选中内容”。普通讨论、图片/音频、非连续或隐藏内容选区不提供替换。
- 点击沿用 ChapterTextModules 的 commit、撤销、格式和原保存CAS流程。保留未选中的前后文、空行及首块ID；原文变化、目标删除/重排、插入其他块、切故事/来源时拒绝覆盖。
- 按钮完成显示“已替换”；正文撤销后可以再次采用。手动改文会显示“原文已变化”。未新增常驻工具栏或确认弹窗。
- 聊天消息保留并校验改写元数据。历史回复没有发送时目标，不能可靠补绑，故不追补按钮；从本轮更新后的新改写开始提供。旧回复仍保留。

## 边界与发布

本轮不调用付费模型；真实供应商对结构化改写的遵循质量尚待用户下一轮实际对话验证。不改变手机旧聊天流程；本能力当前入口为桌面书稿聊天。老排版画布、媒体、非连续多选和折叠隐藏内容不提供直接替换。
