# 统一版本对比与跨标签页更新 — 本地验收

## 用户要求与实现

- 合并“对比生成的文字”“当前版本与分享记录”及历史入口为“版本”。同一列表保留生成稿、收到稿、编辑者、用户自填说明、旧版本和分享记录。章节工作区不再重复显示顶层文字历史。
- 文字左右并排：左侧所选稿只读、可选中复制，用删除线标红删掉的文字；右侧当前稿可以直接编辑，新增文字标红并随输入更新。窄屏维持两列、横向滚动。
- 编辑复用 ChapterTextModules，保留块身份、标题结构、回车/粘贴、中文输入、撤销与聊天定位。浏览旧稿不自动保存或采用；采用先保存当前稿，再通过原接口恢复/接收。

## 多标签页问题

- `pnpm env:status` 与监听端口检查：仅主仓库 3000 正在运行，worktree 无服务和业务数据。浏览器同时开着 localhost:3000 与正式站，它们并非同一个数据环境。
- 只读观察发现，同一篇真实故事旧标签停在旧的本机草稿，新开的标签能读到已保存的最新内容。未修改该真实故事。
- 原章节读取关闭聚焦刷新，编辑器也没有跨标签页更新处理。新增聚焦、可见性以及每15秒可见页读取检查；请求不直接写入当前查询缓存。
- 正文无独立未保存修改、排版队列为空，且共享草稿缓存没有其他内容时，更新到新服务器版本；否则保留当前稿并在“版本”提示更新。离开故事忽略迟到请求。
- 有冲突的当前稿，只有明确打开服务器最新版本对比后才允许基于该比较版本保存；仍使用 expectedVersion，期间再次并发修改会拒绝覆盖。采用先存本页草稿再恢复所选版本，双方文本保留于历史。
- 本页保存成功只清理与本次提交完全相同的缓存，不清理别的标签页已写入的不同草稿。

## 防止复发（后续补充）

- 用户进一步确认问题发生于 Codex 浏览器与 Chrome 的面试故事“VC们”。只读检查 Chrome 标题已改，页面却明确显示“未保存 · 草稿保留在本机”；这部分输入尚未提交服务器。未替用户保存/刷新真实草稿。两个浏览器的 localStorage 不共享，未保存输入不视为已同步。
- 缓存正文新增 baseVersion。没有基准号的旧缓存只保留供对比，不用当前服务器版本冒充写作起点；陈旧基准同样阻止直接保存。打开最新稿比较后，提交以读到的快照版本做 CAS，不因再次发生并发修改而自动重试覆盖。
- 组件测试确认未知/旧基准时 save 不调用、缓存不删除；明确比较后可保存且不把 baseVersion 混入服务端正文。接口测试同时提交两份同基准文本，仅一份成功，原文保留；比较期间又有新稿，过期比较提交失败且最新文本不变。
- 线上 MySQL 路径代码核对：saveChapterContent 使用 transaction + SELECT FOR UPDATE，锁内核对 expectedVersion，再保存旧版和新稿。本轮没有连接正式数据库执行并发测试；接口测试使用 Vitest 隔离的临时目录，不能当作生产数据库实测。
- 每天出现的“旧草稿未归属”横幅取消，改为头像菜单“找回本机旧内容”。只在实际有可读记录时出现；弹窗列标题/日期/文字预览，说明用途，仍需确认归属后复制。无自动删除或自动导入。
- 浏览器虚构故事1210：正常打开无横幅；账号菜单主动打开、选择旧虚构稿可见预览；关闭并刷新测试页不自动提醒。没有恢复或删除旧稿。
- `pnpm verify:draft-safety`：7个文件62项通过；已作为 `pnpm build` 的首个步骤，失败终止构建。覆盖旧稿/未知基准、明确比较、保存失败、跨标签草稿、焦点刷新、离线/迟到读取、保存队列、账号认领、服务端并发和历史保留。直接绕过该命令手工调用 vite 不受此门禁保护。
