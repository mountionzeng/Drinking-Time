# 手机书中模块编辑接入

状态：本地接入完成，未部署。原生小程序由文档04对话另行实现，不能将本页 Web 证据当作小程序验收。

## 实现

- 手机故事页“编辑书中模块”进入共享 ChapterWorkspace；保留 MobileStoryTags 与原有文字稿/图片/视频入口。
- 同一账号/故事复用电脑章节书稿、writingStyle、CAS、恢复缓存、版本和转换接口；不把旧 publishing 正文覆盖进已有书稿。原文字稿仍为独立稿件，不自动反向采用书稿内容。
- 没有已有书稿时沿用现有章节初始化，首次模块编号和样式写入原保存机制；修复纯文字旧稿打开转换时后台“请选择文字或图片模块”。保留换行和已存在的模块编号。
- 小屏重排保持正文字号至少16 CSS px（默认文章缩放），只改变视图宽度，不写回设备专属版式。格式菜单可滚动、选中缩放角点可见；菜单多选可点选多个模块并合并。
- 选中模块经既有 MobileMemoryFollowup 传给小鸟，按账号/故事/章节作用域拒绝跨故事上下文。
- 退出模块编辑先等待共享书稿保存，失败保留编辑页。加载模块入口不再闪现图库。

- 旧稿修复前有声书报价报“请选择文字或图片模块”；修复后同一模块真实报价成功：确认按原文朗读（0.04算力）。未确认付费生成。
- 向空白文字模块写入“手机模块保存验收。”，出现已保存；返回文字稿再重开书稿，测试段仍在。原文字稿未被替换。

## 限制

- 真机系统键盘、连续触摸拖放/裁切、多选整体变换尚未做完整手机设备验收；这里只确认浏览器预览及共享逻辑回归。
- 图片/音乐/有声书实际生成继承既有供应商缺口。本次不重复提交付费任务；报价通过不等于生成成功。
- 原生小程序目前负责对话已报告字号控制及1601项测试通过，其余功能继续处理中，尚未提审。

## 手机入口可见性补修

- 手机首次打开 `/editing` 使用手机工作区；仅挂载时选择设备，调整电脑窗口大小不卸载正在编辑的稿件。
- 手机故事首页直接显示“编辑书中模块”，点击即进入共享书稿，不必先找旧文字稿里的二级入口。其他阶段入口和标签保留。
- AppRouter、MobileStoriesPage、MobileStoryWorkspace、MobileWorkspace 共53项通过；`pnpm check`及定向diff检查通过。
- Chrome 390px实际打开 `/editing` 显示手机工作区，点击首页按钮直接进入手机书稿；保存的“手机模块保存验收。”仍在，版本/生成图片/添加音乐入口可见。
- 原生主仓开发工具检查：故事→章节当前仍是普通文字编辑区，字号/裁切的实际入口尚在与原生负责对话核对；不能宣称原生模块转换已可用。

## 默认模块编辑与触屏操作（用户再次反馈后）

- 原因：直达storyId仍打开旧整篇文字稿；模块格式按钮依赖选中，触屏不易发现。
- 手机工作区首次文字故事默认进入书稿；图片/视频明确阶段保留。书稿返回仍可查看旧文字稿，不反向覆盖。
- 触屏模块格式按钮常显“操作”，保留既有转换/保存接口；仅书稿中小鸟缩至右下角，并移除遮挡正文的渐隐层。
- Chrome 390px打开 `/m?storyId=1214` 直接呈现三个文字模块；实点“模块1格式”显示生成图片/音乐/有声书，再点有声书进入转换对话框。未提交付费生成。截图检查按钮可见且小鸟不再大面积盖住正文。
- 41项相关测试、类型检查通过。右侧内置浏览器工具权限仍受限，不把Chrome证据冒充其验收；未部署。
