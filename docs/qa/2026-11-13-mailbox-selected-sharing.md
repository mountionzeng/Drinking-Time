## 实际实现

- Web 邮箱保留完整故事发送，增加段落、插图、图片、就绪视频/声音/成片的勾选及发送目的地。即使没有 Web 联系人，也可准备本人小程序接收。
- 局部内容从白名单重建，不携带未选正文、发布镜像、历史、剪辑线、生成提示词、聊天或来源图片。所选内容身份写入不可变快照，双方后续保存只刷新原选范围；新内容默认私密。
- 接收后建立独立故事，重映射段落/素材身份，回传继续保持原范围；删除段落不把邻居移入范围。旧无稳定段落 ID 的正文按内容摘要绑定，改文需重选。
- 对话可列出可发送部分、使用邮箱当前勾选与目的地、预览并明确确认发送。缺少选区的局部请求不会退回整篇；切换账号/故事/选区/目的地使旧前端待确认失效。
- 小程序扫码只预览；本人点击确认才绑定内容接收渠道并存下不可变私密来稿。这是独立内容绑定，不合并登录身份/余额，不替换原邮箱 OTP 导入。
- 小程序入口为“我的 → 网页寄来的故事”，独立只读显示文字、图像、现成视频/声音。本人点准备分享后才有微信原生好友选择器；任何取得有效链接的微信用户可查看。反复准备分享保留旧链接，撤销后旧链接及受管媒体签名失效，重新开启生成新链接。
- 0042 只新增绑定和来稿两表；已有表不改、无账号回填。收件列表 SQL 只读标题等摘要，不读取全部正文。服务端有用户行锁/本地聚合回滚、幂等请求及暂存文件清理。
- 复用既有 `/v1/web-login/qr`，新可选 purpose=mailbox 固定 `wm_` 场景及新页面；旧无 purpose 登录协议不变。小程序桥接严格验证响应形状，可信主体来自云端 APPID/OPENID，HMAC/持久 nonce/限流保持。
