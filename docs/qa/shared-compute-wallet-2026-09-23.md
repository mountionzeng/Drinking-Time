# 共享算力实现与上线闸门

状态：部分实现，未合并、未部署。不能宣称手机真实 AI 消费已扣账。

## 已实现

- 同一权威 userId 读取同一账本；新增 HMAC 签名 `/api/shiguang/compute/balance|reserve|settle`，复用持久化 nonce 与限流。
- 操作按账号隔离，复用账本幂等逻辑；异常负余额不伪装成零余额。
- 首次赠送按账户锁及历史赠送键前缀去重；多身份并发不会重复赠送，不主动合并两个已有账号。
- 用户页面、报价和系统提示使用算力；本机不限额保留，累计用量保留微量精度，前台每 5 秒刷新。
- 手机独立工作树加入只读余额入口及页面轮询；身份沿用电脑配对 APPID+OPENID 哈希，不接受客户端主体或金额。
- 现有身份、家庭、故事、图片与旧兼容余额字段未迁移或删除。

## 验证

- 桌面 19 个定向测试文件 237 项通过；共享桥使用真实账本进行 HTTP 集成测试。
- 原生小程序测试 215 项、小游戏账单 3 项通过。
- 手机 `npm test`：821 项通过；两仓类型检查通过。
- 测试使用隔离数据与模拟供应商，不修改用户业务数据，不发生真实 AI 调用。
- 尚未执行真实 MySQL 并发、页面视觉验收或手机完整真实消费流程；未提供预览二维码。

## 上线前仍需完成

1. 手机文字、图片、语音接入预占、结算及异常对账。当前只有日限额，没有金额扣账，不能以次数冒充费用。
2. 确认 TokenHub 各模型的费用回执/计费表与币种；超时、重试和异步状态不明确时保留待对账，不能默认免费，不能把估算标为实收。
3. 桌面配置 `SHIGUANG_COMPUTE_ENABLED=true`、权威账户数据库和 `SHIGUANG_BRIDGE_SECRET`。getOpenId 云函数配置同名开关及 `DRINKING_TIME_BRIDGE_SECRET`、`DRINKING_TIME_BRIDGE_BASE_URL=https://<指定服务>/api/shiguang`。密钥仅存服务端。
4. 核对同账号电脑短码与手机读取；已有两独立账户冲突不自动合并，不叠加赠送。AppID 迁移别名跨主体钱包仍需专项核验。
5. 与手机文字及图片任务协调集成，确认两端部署范围；真实验证双账号隔离、登录赠送、消费、断线重试、异步对账与跨端刷新后再交付。

## 上线后监测与回退

观察 `compute_unavailable`、`compute_reconciliation_required`、验签失败、重放、限流及预占积压；日志不含密钥、正文或照片。正常信号是同账号两端一致、赠送仅一笔、每操作最多一笔消费。出现跨账号读取、重复赠送或扣款、账目负值时关闭共享扣账入口，保留账本和预占进行对账，不清空用户资料。负责人及观察窗口在确认部署时指定。本轮没有线上变更。
