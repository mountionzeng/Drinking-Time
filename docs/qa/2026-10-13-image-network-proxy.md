# 图片生成失败：本地出站代理修复

## 实证

- 主仓唯一3000服务，故事1206最新封面操作在20:01:04开始，11,183ms后失败；provider为midjourney，taskId为空、候选轮数为0。失败位于文字配图准备，尚未提交图片任务。文字准备账单结果不确定，不能宣称完全无费用。
- 系统DNS为198.18.0.2，系统已启用127.0.0.1:7890的HTTP/HTTPS代理。
- 沙箱外直连AI域名约6秒DNS解析超时；通过同一系统代理，无凭据HEAD检查Next返回200（2.09秒）、302返回200（2.26秒）。
- 原`configureHttpConnectionPool`始终安装裸Undici Agent，覆盖Node代理支持；本地后端因此绕过可用系统代理。此前更换文字模型没有解决这一网络根因。

## 修复与限制

- 连接池尊重环境代理及NO_PROXY；仅macOS development在没有显式环境代理时读取系统已启用的loopback HTTP/HTTPS代理。
- 不写死代理端口、不修改系统或业务数据；保留连接复用、TLS校验、模型配置、费用确认、任务恢复与不确定提交禁止自动重放规则。
- localhost及loopback保持直连；生产/测试不探测系统代理；development显式DEV_USE_PROXY=0可以关闭代理。
- 用修复后的同一模块实际HEAD验证：localhost200/20ms，Next200/5,254ms，302200/2,299ms。网关连通不等同于模型生成成功。
