# 对话改图：输入、预览与明确替换

用户要求：思考/制作期间能继续输入其他内容，新图在对话展示，随后用文字决定是否替换原素材，不增加按钮。

## 诊断与实现

- 原确认分支无论是否匹配回答均提前返回，选中图片且 isReplying 时发送按钮还被禁用。现在只消费明确确认/取消，其余文字进入原有持久队列；明确选图指令冻结图片身份和模型。任务受理即释放普通对话，其他文字继续处理。
- 原 referenceRevision 的后台受理被当作普通错误；任务结果可能入库却没有聊天预览。聊天路径复用 storyboardImageTasks，保存 exact parentImageId、稳定镜号、意图、时间、供应商回执；GPT submit-only，MJ 原受理机制，恢复只查询已有任务。供应商明确失败停止查询，未知受理不重购。
- 对话底部新增无操作按钮的图片预览：镜号、原图、真实候选编号；刷新后从服务端任务恢复。历史图片用持久 parentImageId 补回预览，未制造新生成结果。新候选先询问“替换原图 / 保留原图”；多张可说“第01镜第2张替换原图”，多轮可用“图片 #编号替换原图”。
- 选择后服务端校验所有权、任务候选及原图关联。原剪辑身份/位置/时长/图层和声音保留，首尾帧引用与决定同一 Story/Timeline CAS 提交；原图为当前主图时再以 expectedCurrentImageId CAS 同步主图投影，重放可补齐同步，不覆盖更新的选择。旧资产不删除。
- 传统非聊天入口自动上方图层行为保留；用户最新修改只作用于对话选图路径。错误在对话反馈，不再额外弹出需要点“知道了”的改图错误框。
- 对话返回合并当前消息，避免覆盖等待期间到达的记录；迟到结果校验账号、故事和 scope/load epoch。
