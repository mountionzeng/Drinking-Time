2026-11-09，唯一主仓 localhost:3000。未提交、未推送、未部署。

## 已定位与修复

- 实际 HTTP 响应包含 `Permissions-Policy: camera=(), geolocation=(), microphone=()`，即使系统已授权，网页也不能请求录音。现改为 `microphone=(self)`，保留摄像头、定位、跨站与嵌入限制，浏览器授权仍必需。
- 修改前新增的开发/生产两项测试均失败；修改后通过。主仓服务自动重载，实际 HTTP 200 响应已返回新策略。
- 电脑 StoryAgentChat 原话筒仍只使用录后转写。现在显式优先复用已有 liveDictation 控制器，中文中间结果进入原输入框，最终结果追加草稿，仍需用户发送。原位按钮不增加，听写中禁止发送，临时文字存在时防止编辑冲突。
- 切换账号/故事或卸载中止识别，拒绝迟到结果。识别失败不自动调用付费备用服务；不支持实时 API 的浏览器保留旧录后转写路径。长供应商错误改为短提示；桌面不再使用阻塞 alert。

## 真实浏览器检查与限制

- 系统设置只读核对：ChatGPT 和 Google Chrome 的麦克风权限已打开；Siri 已打开、语言为中文普通话，未修改系统开关。
- 修复响应头后，新开的右侧内置浏览器仍立即拒绝 getUserMedia。网站策略不是它剩余拦截的唯一原因，不能宣称内置浏览器已可录音。
- Safari 已存在的标签显示旧接口的豆包403/302 500。新标签加载修复后，实点原话筒弹出“允许 localhost 使用你的麦克风”，按用户试录授权允许后关闭测试标签，未点击停止提交转写。这证明授权提示可以出现，不证明录音或完整转写成功。
- 接入桌面实时识别后，Safari 实点话筒，15秒内没有收到识别启动事件，显示“未能启动听写，请检查浏览器的麦克风与语音识别权限”。没有产出文字，不能将模拟测试当作真实成功。
- Chrome 同一主仓页面作为对照，实点原话筒后出现“听写中，文字会显示在输入框”及“停止录音”，停止后真实识别文本进入草稿，未触发旧转写接口、未发送消息。测试前输入框为空，测试结束已清空这次识别出的草稿并确认发送按钮禁用。截图 `/private/tmp/desktop-live-dictation-chrome-20261109.png`。这证明 Chrome 实时链路可启动并出字，不代表识别准确率、Safari 或双手机通过。
- 开发热更新增加 hook 后 Safari 曾显示 React hook 热更新异常；完整刷新后恢复原话筒与空输入框。
- 普通录后转写仍调用没有权限的 `volc.bigasr.auc_turbo`，302备用返回500；素材收集标准 ASR 是独立持久任务链路，不能直接把其成功视为普通聊天成功。本次没有改后端供应商或触发新的付费转写，没有自动发送消息或改写书稿。
