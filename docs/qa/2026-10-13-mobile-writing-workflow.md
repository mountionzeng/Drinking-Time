# 手机统一聊天与文字版本流程（2026-10-13）

## 授权与范围

用户要求将已经验收的电脑“聊天提议 → 生成新版本 → 预览 → 保存”迁移到手机，并把普通聊天与正文伴写合并到一个入口，只补必要按钮。沿用现有六种主题、底部角色与开合动画。本次不提交、不发布、不调用付费模型、不改写真实文章。

## 实现

- 底部小忆根据当前回忆/文字/视频携带上下文；文字讨论把完整可见正文（含未保存内容）和明确选区传给 `replyAsWritingCompanion` 的 `fullDraft` 模式，打开入口不推理。记忆与视频原有来源引用和导入/标记/加入文字能力保留。
- 正文页删除独立伴写弹窗入口；修订弹窗内原入口改为打开同一个小忆。选区以 textarea 原始偏移传递，服务端机械保留选区外内容。
- `MobileTextDraftFlow` 使用与电脑相同的 `textDrafts.generate/adopt/read`。生成和保存独立，预览可修改；候选及修改按账号/故事在本机恢复。已保存历史保留。
- 生成前捕获发布修订号，保存不自动刷新掉冲突保护。网络响应不明先查询原候选；确认无记录时允许显式重发同一token与原请求，由服务端去重，不自动重购推理；保存丢响应检查相同候选的采用内容。冲突展示最新正文供用户核对。
- 手机发送时立即排队并展示原话；逐条回复/同步后才继续。失败/未知轮次暂停；刷新后需显式继续；写作上下文随各条消息保留。
- 已采用候选仅在原编辑缓冲、发布范围和正文修订都未变化时清理相应本机缓冲；其他新输入保留。

## 验证

- `pnpm env:status`：仅主仓端口3000，无工作树服务。
- 33个相关测试文件313项通过：手机工作区、共享伴写、电脑文字版本和发布区、服务端会话与生成/采用。
- 新增真实路由集成测试在Vitest临时数据目录中运行，仅模型返回被模拟：聊天提议、完整轮次落库、生成候选、原文不变、显式采用、重新读取正文与历史一致；相同token不重复推理；选区外原文保持；电脑新修改导致冲突；其他账号无权读历史。
- 收尾变更后29文件237项及来源完整性2文件6项通过。
- 队列恢复测试覆盖排队消息/完整正文/选区的保存，旧未知或失败轮次不被跳过。
- TypeScript与生产构建通过（既有大chunk警告）。
- 主仓真实浏览器390×844：打开当前正文的小忆后只有一个聊天框，显示“正在讨论当前文字”及“生成新版本”；原有导入/记忆/文字操作仍可见。打开既有虚构故事的待采用文字，实际进入全文预览，显示“保存新版本”；没有点击采用，也没有调用生成。

## 验收边界

本次完整生成/保存链使用模拟模型与真实路由/隔离持久化验证；浏览器验收当前上下文入口与现有候选预览。真实供应商时延/质量、iOS/Android软件键盘、真实弱网和公网双设备并发尚未验收。手机速度不等于模型速度，未宣称原来约76秒的生成耗时已解决。旧独立伴写组件仍保留为兼容代码，但产品中不再挂载独立聊天入口。
