# 手机一键实时听写

2026-11-09，本地主仓 3000；未推送、未部署，尚未完成 iPhone/Android 真实听写及系统分享验收。

## 问题和根因

用户在 iPhone 正式站点击话筒后看到“开始录音”及完整服务报错。旧 MobileVoiceInput 第一次仅挂载 RecordingControl，必须第二次点击才请求麦克风；useVoiceInput 只在 MediaRecorder 停止后提交转写，无法实时出字。截图中普通语音路径使用豆包极速版 volc.bigasr.auc_turbo，权限403后302回退500；素材收集使用的标准ASR路径是另一条服务，不能以它的成功代替普通语音验收。

## 当前实现

- 保持原位单个话筒，点击原手势中启动 SpeechRecognition / webkitSpeechRecognition，启用中文、连续识别和中间结果。开始后同一图标变为停止；不增加开始按钮或配置菜单。
- 中间结果显示在输入框并随识别修正；暂时只读以避免用户改字与识别修正互相覆盖。确认的片段追加已有草稿，停止后可编辑、由用户发送，不创建故事或自动发消息。确认片段沿用现有草稿保存；未确认的中间片段不承诺刷新恢复。
- 结果按索引去重；停止后等待末次结果，浏览器不结束时1.5秒释放并保留最后可见文字。网络错误保留已识别文字；等待启动15秒超时，单次最长10分钟。关闭/卸载中止识别并拒绝迟到回调，不写新会话。
- 没有浏览器识别API时，一次点击启动已有录后转写兼容路径并明确提示。上游失败只显示短句，放在输入栏上方整行，避免原来窄栏把输入框挤走。不自动重试或换付费供应商。
- 听写期间禁用发送和素材切换；既有“添加素材 → 录一段”仍负责保存音频原件，系统分享实现不变。实时听写没有可回听音频文件。
