# OpenAI Next 扩大算力接管范围

## Summary

让 OpenAI Next 接管所有协议兼容的文本、结构化 JSON 与视觉理解请求；登录欢迎页的访客回信使用 `deepseek-v4-flash`，302 收敛为兼容回退及媒体生成、语音等专用能力供应商。

---

## Problem Frame

项目已经把部分文本和视觉理解负载迁移到 OpenAI Next，但通用故事 Agent、镜头拆解及若干旧调用仍可能绕过统一路由直接使用 302。结果是同类能力由不同供应商承载，难以确认一次请求实际走向，也无法充分利用 OpenAI Next 已提供的模型额度。

现有 302 调用还混合了两类本质不同的能力：一类是兼容聊天补全协议的模型推理，另一类是图片、视频、语音、转写及带任务回执的付费媒体服务。若不明确边界，扩大迁移容易破坏已生成素材、任务恢复或防重复扣费机制。

---

## Key Flows

- F1. OpenAI Next 正常承接
  - **Trigger:** 用户触发故事回复、摘要、意图识别、镜头拆解、选择编辑、提示词整理、结构化分析或视觉理解。
  - **Steps:** 系统识别请求类型，选择 OpenAI Next 支持的文本或视觉模型，完成请求并返回现有业务结果。
  - **Outcome:** 用户体验和数据格式保持不变，模型推理额度计入 OpenAI Next。
  - **Covered by:** R1, R2, R3, R4

- F2. OpenAI Next 不可用时回退
  - **Trigger:** OpenAI Next 未配置，或当前请求无法由其兼容通道完成。
  - **Steps:** 系统按既有边界回退到 302；若两个远端通道都不可用，则沿用已有本地保底或明确失败行为。
  - **Outcome:** 扩大迁移不降低现有功能可用性，也不产生重复付费提交。
  - **Covered by:** R5, R6, R7

- F3. 媒体与语音专用任务
  - **Trigger:** 用户生成或编辑图片、生成或扩展视频、合成语音或执行音频转写。
  - **Steps:** 系统继续使用既有专用供应商协议、任务编号和恢复机制。
  - **Outcome:** 已有素材、任务状态和防重复扣费保护保持有效。
  - **Covered by:** R6, R7, R8

- F4. 登录欢迎页访客回信
  - **Trigger:** 未登录用户在欢迎/登录页提交情绪资料并请求访客回信。
  - **Steps:** 系统保持现有限流和不落账号画像的边界，通过 OpenAI Next 的 `deepseek-v4-flash` 生成回信；模型不可用时使用既有本地保底。
  - **Outcome:** 登录前体验使用指定模型，但邀请码身份认证始终不依赖大模型可用性。
  - **Covered by:** R11, R12

## Requirements

**接管范围**

- R1. 所有兼容聊天补全协议的通用文本推理应优先使用 OpenAI Next，包括故事 Agent、故事回复、摘要、意图识别、镜头拆解、选择编辑、提示词整理和结构化分析。
- R2. 通用文本请求默认使用已实测可用的 `gpt-5.6-terra`；不得因旧调用保留的 302 模型名而绕过 OpenAI Next。
- R3. 兼容的视觉理解请求应继续优先使用 OpenAI Next 的视觉模型，不把图片内容分析误归类为图片生成。
- R4. JSON 输出、推理强度、token 上限和多模态消息等请求能力应按目标模型兼容性处理，不能因单个不兼容参数让整类请求退回 302。

**回退与专用能力**

- R5. OpenAI Next 未配置时，兼容请求应回退到现有 302 通道；两个通道均不可用时保持现有本地保底或错误语义。
- R6. 图片生成与编辑、视频生成与扩展、TTS、音频转写、Midjourney、GPT Image 及依赖异步任务回执的能力继续使用现有专用通道。
- R7. 已受理的付费任务不得因供应商路由变化自动重提；原任务编号、恢复流程和防重复扣费保护必须保留。

**数据与可验证性**

- R8. 迁移不得修改或重建现有故事、图片、视频、编辑快照和本地持久化数据。
- R9. 每次兼容模型请求应能从安全诊断信息确认实际供应商与模型，但不得记录 API Key 或完整私密内容。
- R10. OpenAI Next 凭据仅通过未提交的环境配置注入；任何测试、日志和版本记录都不得包含真实 Key。

**登录欢迎页**

- R11. `/login` 与欢迎页共用的访客回信请求应使用 OpenAI Next 的 `deepseek-v4-flash`，与通用故事 Agent 的默认文本模型分开配置和观测。
- R12. 大模型不得进入邀请码校验、会话建立或账号认证的关键路径；访客回信模型失败时必须沿用本地保底，不得阻止或延迟用户登录。

## Acceptance Examples

- AE1. **Covers R1, R2, R9.** Given OpenAI Next 已配置，when 用户触发故事回复或镜头拆解，then 请求使用 OpenAI Next 的 `gpt-5.6-terra`，诊断信息可确认供应商与模型，业务返回格式不变。
- AE2. **Covers R3, R4.** Given 用户提交图片进行内容理解，when 目标视觉模型支持该输入，then 请求由 OpenAI Next 完成；若某个可选参数不受支持，系统调整参数而不是直接切回 302。
- AE3. **Covers R5.** Given OpenAI Next 未配置，when 用户触发兼容文本请求，then 系统沿用 302 回退；若 302 也不可用，则使用该功能原有保底行为。
- AE4. **Covers R6, R7.** Given 302 已受理一个图片或视频付费任务，when 服务重启或用户刷新，then 系统恢复同一个任务，不向 OpenAI Next 或 302 重复提交。
- AE5. **Covers R8, R10.** Given 迁移前已有故事和媒体资产，when 迁移完成并重启主服务，then 数据数量和关联关系保持不变，版本差异中不存在真实凭据。
- AE6. **Covers R11, R12.** Given 未登录用户在 `/login` 提交访客回信资料，when OpenAI Next 可用，then 请求使用 `deepseek-v4-flash`；when 模型不可用，then 返回既有本地保底且邀请码登录仍可正常完成。

## Success Criteria

- 兼容文本与视觉理解的生产调用不再无意绕过 OpenAI Next。
- 用户可以安全确认一次调用使用的供应商与模型，无需暴露输入内容或凭据。
- 302 的剩余调用都能归因于明确的回退或专用媒体、语音协议，而不是历史遗漏。
- 现有故事、图片、视频和编辑快照保持完整，相关自动化测试与真实最小请求验证通过。
- 登录欢迎页的访客回信可确认使用 `deepseek-v4-flash`，且认证链路在模型故障时仍独立可用。

---

## Scope Boundaries

- 不把 OpenAI Next 当作图片生成、视频生成、视频扩展、TTS 或音频转写供应商。
- 不迁移或重写既有媒体任务记录，也不批量修改现有故事和素材数据。
- 不在本轮引入面向用户的模型选择器、计费面板或多供应商负载均衡策略。
- 不仅为了使用更多模型而改变现有创作功能的产品行为或输出结构。
- 不让大模型判断用户身份、邀请码有效性、登录权限或会话是否建立。

---

## Key Decisions

- 以能力协议而非厂商品牌划分边界：聊天补全与视觉理解优先 OpenAI Next，专用媒体和语音任务保留原通道。
- 使用一个稳定的默认文本模型完成本轮收敛，避免不同功能随意选择模型造成不可预测差异。
- 302 保留为兼容回退而非被彻底移除，以维持本地创作流程的容错能力。
- 供应商和模型来源必须可观测，因为可验证的迁移比仅修改配置更可靠。
- 登录欢迎页使用独立模型档位，避免为升级访客回信而改变登录后每日回信或通用故事 Agent 的模型行为。

---

## Dependencies / Assumptions

- OpenAI Next 持续提供兼容的聊天补全接口，并保持 `gpt-5.6-terra` 与已配置视觉模型可用。
- 现有 302 专用媒体、语音和异步任务接口继续有效。
- 规划阶段需要逐项审计剩余旧调用，区分真实 302 依赖与仅含历史命名或测试样例的代码。
