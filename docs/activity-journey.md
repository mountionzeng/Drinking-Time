# 网站创作漏斗 · 事件版本 2

入口为现有 `/admin/users` 的「创作漏斗」。默认关闭采集，`ACTIVITY_JOURNEY_ENABLED=true` 才允许写入。这里沿用 PR #16 的四个阶段名。历史 PR 的提交以供应商任务号为准，版本 2 以网站的业务端首次持久接单为准。版本 2 读写 `activity_journey_v2_events`，历史事件和指标保持各自口径。

| 事件 | 证据和写入点 | 去重范围 |
| --- | --- | --- |
| `creation.entered` | 网站客户端在已登录状态进入 `/editing`、`/creation`、`/m` 或 `/stories` 创作界面，服务端接收导航信号 | 账号与浏览标签页会话。刷新和同一会话返回沿用键 |
| `generation.submitted` | 网站请求首次持久化出图任务、书稿模块图片任务或指定视频 Take。服务端入队与供应商接收是两个时点 | 账号、媒体种类、内部任务 UUID 或 Take ID。同一业务请求沿用已有幂等键 |
| `generation.resolved` | 图片候选事务提交，有正整数 ID 和可用地址。视频 Take 已持久化为 `available`，同时有托管文件键和用户可用地址。失败、取消、超时和结果未知按独立证据写入 | 同一尝试、状态、内部结果编号。一个尝试可有多张候选 |
| `result.opened` | 手机网页账号图片库点击放大、Animatic 素材库点击视频预览。服务端核对同账号成功事件和现有结果归属及可用状态 | 同一尝试、种类和结果编号的首次查看。刷新、重复预览和网络重试共用键 |

界面打开说明用户触发了预览。鼠标悬停、自动挂载和后台轮询没有查看信号。现行生产的聊天大图预览继续可用，该入口的埋点仍暂缓。供应商返回、HTTP 成功、预占、结算及扣费各有自己的业务含义。统计成功要求入库结果可用的证据，记录时不额外请求媒体文件。

## 采集范围

| 类型 | 显式覆盖 | 证据缺口 |
| --- | --- | --- |
| 图片 | 普通类型的持久图片任务。书稿模块同步事务及明确的恢复入库、异步任务。移动网页路径在登记已有回执时可覆盖后续入库 | 直接同步出图、旧分镜任务、低清草稿、局部修复和其他非上述入库路径。旧模块恢复中的供应商报错若仍保留原回执，当前缺可靠终态 |
| 视频 | `startEndShotVideoWorkflow` 的远程首尾帧 Take。Vidu 明确取消单列。托管前只有外部链接的情况为未知 | 审阅候选、仓库多段合成、普通无稳定业务键的视频提交、本机运动转换、后期修订、网页其他播放器；查询故障只能按既有证据归类 |
| 文字 / 音频 | 使用原有创作与账务数据源 | 本版漏斗未接文字、音乐、配音、朗读和转写 |
| 原生小程序 | 保留报告来源列 | 无新采集。网站登录方式、用户资料和旧订单均无法证明本次请求来自哪一端 |

## 隐私与口径

`platform=web` 的来源证据来自已认证的网站同源变更请求，要求 `Origin` 与服务端 `APP_ORIGIN` 一致、`Sec-Fetch-Site=same-origin`，以及浏览器标签页 UUID。新增的 `x-dt-creation-visit` 请求头只携带 UUID，数据库保存按账号哈希的会话键。异步阶段只跟随原提交上的来源。缺少来源证据的历史数据保留来源未知，新表没有历史回填。

内部字段限于 `userId`、`schemaVersion`、`platform`、`eventName`、`result`、`subjectKind`、`subjectRef`、`visitKey`、`attemptKey`、`dedupeKey`、`occurredAtMs`。客户端只允许进入或结果查看信号；账号从登录上下文取出。结果关联仅在受控服务端使用。后台及 CSV 返回来源、当前账号分类、窗口、观察截止和汇总数字。

日期筛选为北京时间自然日，起点包含、结束日次日零点排除。选择 1–30 日，可按来源、当前账号分类筛选。四类为自己的账号、测试、外部、待确认。空标签归待确认。每个来源和分类组合内按账号编号去重。分类采用查询时的标签，同一账号可能出现在不同阶段。

- 进入队列以窗口内已记录的进入事件为锚，按账号与同一标签页会话键关联该时刻及之后的提交。提交可以跨日或晚于窗口结束。只在另一会话提交时，仍计入对应日期的提交队列。首次进入已在窗口之前的会话不会因刷新进入当前队列。
- 提交队列按窗口内已持久化的提交尝试计算，跟踪同一账号、尝试、媒体种类的结果。成功有多张候选也计一次；查看需与该次成功的结果编号一致。观察截止包含当毫秒，取查询时刻与结束日次日零点加 30 天再减 1 毫秒中的较早者。30 天从窗口结束算起，两个队列共用这个截止。
- 成功率 = 成功尝试 ÷ 全部提交尝试，分母含取消、超时、未知和无结论。明确终态成功率 = 成功尝试 ÷（成功 + 明确失败尝试），分母只有这两类。查看率 = 有查看的成功尝试 ÷ 成功尝试。进入转化率 = 同浏览会话进入后提交的账号 ÷ 进入账号，分子不因该提交后续的结果状态而变化。分母为零时输出空值。
- 成功证据优先，其次为最后一个明确失败或取消，然后才使用最后一个超时或未知。没有结论的已提交尝试单列，包含仍在处理和未观察到结果。一个账号可以有成功和失败的不同尝试。
- 新事件使用 Unix 毫秒，显示固定为 UTC+08:00。旧访问或账务时间仍由原查询从原字段解释。历史连接时区、服务器时区或导入偏移需要单独核对。

查询和 CSV 均使用 `adminProcedure`。查询最多处理 25,000 条事件，超过时要求缩小区间。CSV 最多 12 行来源和分类组合。客户端信号按账号每分钟最多 30 条。数据库采集异常只记固定诊断文本，最多四个在途采集写入，单次最多等待 150 ms。迟到、丢失及开关窗口均会造成漏记，请在出数时标注。

## 只读接口

管理员可展开 `/admin/users` →「创作漏斗」查询或下载纯汇总 CSV。服务端入口为 `adminUsers.journeySummary`、`adminUsers.journeyExport`。输入 `from`、`through` 两个 ISO 日期；可选 `platform` 与 `category`。注册与账号分类继续使用 `adminUsers.overview`，账单及充值继续使用原算力查询和后台。

新表的只读通道需单独核对现有权限；旧账号可读范围以已授权的数据集为准。禁止把缺表、空窗口、无权限或开关关闭解释为无用户行为。
