# 私人美术策展库

这不是公开素材库，也不是训练集。它只负责把创始人认可的图片提炼成可泛化的美术 DNA，交给全站唯一的提示词工程入口 `server/services/renderGate.ts` 使用。

## 安全边界

- 原始截图只作单独的策展分析，不在每次出图时发送给图片模型；“本地文件”不代表模型离线推理。
- 运行时只读取 `curator-profile.json` 和 `catalog.json` 中已经派生、清洗后的美术 DNA。
- 水印、文字、作者签名、账号、手机状态栏、应用界面和截图黑边永远属于污染层。
- 不复制参考图的人物身份、具体物体、地点、情节、作者签名或现成构图。
- 来源或权利状态不明的图片不得用于官网展示、商业素材分发、模型训练或直接风格迁移。

## 文件

- `curator-profile.json`：人工确认的集合级审美底线；`catalog.json` 中 ready 的 DNA 只在情境匹配时提供候选方法。
- `catalog.json`：图片清单、内容哈希、分析状态、权利状态和派生 DNA。
- `references/`：本地私有源图。新导入图片被 `.gitignore` 排除，不能继续提交进 Git。

旧的 `metadata.json` 和 `rules/global-rules.md` 已移除，避免出现多个互相冲突的信息源。

## 添加更多图片

先预检，不会写入、不会调用 AI：

```bash
pnpm art:import -- "/Users/yuandai/Desktop/仓库" --dry-run
```

确认后同步。导入只复制和登记图片，不产生模型费用：

```bash
pnpm art:import -- "/Users/yuandai/Desktop/仓库"
```

新图片会进入 `pending-analysis`。查看待分析数量不会产生费用：

```bash
pnpm art:analyze
```

只有明确加入确认参数才会调用付费视觉模型：

```bash
pnpm art:analyze -- --limit=10 --confirm-paid-analysis
```

分析结果会再次经过污染词过滤；只有状态为 `ready` 的派生 DNA 才能参与线上情境匹配。

## 开放的多标签提取

一张图允许同时拥有多个标签，标签可以交叉，不要求归入唯一流派。不能确定的维度留空，其他可用维度照常保存；旧记录仍兼容原有的风格、色板、光线、构图、材质和情绪字段。

先自由观察，再归类：分类只是索引，不是提取范围。除用户列出的艺术家、构图等维度外，也保留可见的光感、图底关系、节奏、视觉重量、透明感、软硬边等。它们只是观察方向，不是每图必填项；无法支持就不写，不从配文反推画面。自由标签负责发现和检索，对应的可执行方法同时落入光线、构图、材质或笔触字段，运行时仍只按内容选择方法。

新的 `dna.artTags` 保存以下维度（标签内容是自由文本，不限于示例）：

| 维度 | 字段 | 示例 |
| --- | --- | --- |
| 艺术家参照 | `artistReferences` | 姓名＋可观察的相似依据；仅表示视觉亲缘，不鉴定原图作者 |
| 流派与艺术语言 | `movements` | 点彩、抽象表现、东方写意，可并存 |
| 媒介 | `media` | 彩铅、水墨、套色版画、拼贴、混合媒介 |
| 构图 | `composition` | 横向展开、偏置重心、局部裁切、疏密节奏 |
| 视角与景别 | `viewpoint` | 俯视、平视、远景、近观 |
| 空间层次 | `spatialLayers` | 平面叠层、前景遮挡、多层纵深 |
| 笔触与边缘 | `markMaking` | 颗粒线条、干刷、渗化、撕纸边缘 |
| 色彩关系 | `colorRelations` | 冷暖对照、低饱和、高明度 |
| 叙事与生命体验 | `narrativeUses` | 重逢、成长、疏离；只表示适用语境，不推测用户状态 |
| 其他标签 | `freeTags` | 前述维度装不下的特点、常见近义表达 |

检索可通过多个维度命中，不需要全部吻合。艺术家姓名只用于内部检索与策展，自动出图使用可观察的画面语言；色板仍按原有规则，不因匹配图片就整套继承。`narrativeUses`、`freeTags` 和 `colorRelations` 用于检索，不作为整套指令注入出图。没有任何匹配证据时不固定套用目录前两张。

排序保留“命中标签数优先”。同分时，以最长的已命中词组作为具体程度的简单指标，例如“颗粒闪光”优先于“颗粒”；未命中的长词不加分，命中数与词组长度都相同时仍保持目录顺序。这不是完整的语义理解，近义说法仍需标签覆盖。

批量脚本使用 `art-curation` 提取模式；普通照片分析的默认字段和调用预算保持不变。分类扩展不自动重分析历史图片，仍需按批次明确授权付费调用。

## 上线迁移

上线前将 `references/` 中现有的 99 张历史图片迁移到私有 OSS bucket，并从 Git 当前版本中停止跟踪。生产服务器只需要部署：

1. `curator-profile.json`；
2. 去除源图 URL、人物和情节信息后的 `catalog.json`；
3. 必要时通过 `ART_REPOSITORY_DIR` 指向只读配置挂载目录。

私有源图 bucket 必须关闭公共列表与匿名访问，使用服务端短期签名读取；图片只在离线分析任务中读取。若要彻底清除 Git 历史中的旧图，需要单独安排仓库历史重写和所有部署端重新拉取，不能在普通功能提交里顺手处理。
